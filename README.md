# Сайт Марии — первая версия

Обновлённая страница, недельная таблица, запрос на занятия и серверная отправка в Telegram. Фото, цены и контакт ожидают согласования. Вместо неподтверждённых отзывов и стажа использован нейтральный текст.

## Перед запуском

1. Отозвать прежний токен через BotFather: он был опубликован в исходном HTML и остаётся в истории Git и копии ai-lending-test. Удаление строки не отзывает токен.
2. Добавить реальное фото с разрешения Марии; сейчас используются инициалы.
3. Согласовать тексты, цены, Telegram и условия обработки заявок.

## Размещение с работающей формой

GitHub Pages исполняет только статические файлы. Для формы нужен сервер: здесь подготовлен Cloudflare Worker. Настройка отдельного хостинга ещё не выполнена.

Установить актуальный Wrangler через npm, затем выполнить `node prepare.mjs`: он копирует index.html, app.js и images/ в public. В public не должны попадать worker.mjs, конфигурация, документация или секреты. Файлы в корне сохранены для совместимости со статическим просмотром старого репозитория.

В wrangler.jsonc заполнить TELEGRAM_USERNAME (без @), PRICE_60 и PRICE_90. Пустые цены отображаются как «Стоимость уточним при знакомстве». Секреты TELEGRAM_BOT_TOKEN (новый токен) и TELEGRAM_CHAT_ID добавить через управление секретами Cloudflare или `wrangler secret put`. Не записывать токен в HTML, Git или чат.

Запустить `wrangler dev` для проверки, затем `wrangler deploy` для публикации. Rate limiter обязателен: без него или без секретов форма отключена. Ограничение — 3 обращения за 60 секунд на IP; оно снижает простой спам, но не заменяет полноценную антибот-защиту. При размещении нескольких Workers выбрать уникальный namespace_id для лимитера.

Проверить реальную заявку после настройки с согласия владельца Telegram. В этой версии реальная отправка не проверялась. Выбор свободного времени — заявка, окончательное подтверждение даёт Мария. Отправка заявки не закрывает слот автоматически.

## Недельное расписание

Каждая неделя заполняется вручную. Время — Asia/Irkutsk (UTC+8). Посетителю доступны текущая и восемь следующих недель; прошедшие часы нельзя выбрать. Новая неделя пустая, пока Мария не добавит время. После выбора сервер повторно проверяет доступность, а в Telegram передаются дата, время и часовой пояс.

Создать Cloudflare D1 базу и добавить в wrangler.jsonc полученный реальный идентификатор:

```json
"d1_databases": [{ "binding": "DB", "database_name": "mklending-schedule", "database_id": "идентификатор созданной базы" }]
```

Применить schema.sql через D1 (локально для проверки и отдельно к production). Например: `wrangler d1 execute mklending-schedule --remote --file=schema.sql`. Секрет ADMIN_KEY установить как случайный ключ не короче 32 символов; не включать его в клиентские файлы или Git. ADMIN_LIMITER уже указан в конфигурации.

Открыть /admin.html на том же HTTPS-домене, ввести ключ. Он хранится только в памяти вкладки. Выбрать понедельник нужной недели, добавить время и отметить «Свободно» или «Занято», затем сохранить. Можно скопировать часы предыдущей недели. Кнопка «Очистить эту неделю» сбрасывает её часы; после этого нужно сохранить. После подтверждения заявки вручную пометить час занятым. Нельзя редактировать расписание одновременно в двух вкладках: при конфликте сохранение отклоняется, нужно войти заново.

Хранятся до 60 недель, до 140 времён на неделю. Для нового календарного года архивные недели нужно убрать из данных через обслуживание базы, либо расширить политику хранения. Персональные сведения учеников в расписании не хранятся. На статическом GitHub Pages база, управление и API не работают; до размещения Worker показывается сообщение о недоступности.

## Локальная проверка

`node --test worker.test.mjs schedule.test.mjs` — проверки входных данных, лимита, ответа Telegram с подменённым fetch, недельных дат, часового пояса, доступа к управлению и конфликтов сохранения. `node --check app.js` и `node --check worker.mjs` — синтаксис. При статическом просмотре без Worker форма честно сообщает о недоступности.

## Защита секретов

Токены не маскируются в браузере: браузер их вообще не получает. TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и ADMIN_KEY задаются как серверные секреты. Публичный /api/config возвращает только возможность записи, контакт и цены. Ключ управления не сохраняется в localStorage или cookie.

`npm test` запускает все проверки, включая security.test.mjs. `npm run build` создаёт public из списка разрешённых файлов и сканирует проект на токены Telegram и файлы с секретами. Wrangler запускает этот шаг перед сборкой; при обнаружении публикация должна остановиться. Сканер проверяет распространённый формат токена и не заменяет ротацию или полноценный аудит. Сообщения сканера содержат только имена файлов, без значений. Не храните рабочие .env/.dev.vars в этой папке при сборке; используйте серверное хранилище секретов.

Worker устанавливает CSP без inline-скриптов, защиту от встраивания во фреймы, запрет MIME sniffing и no-store для страницы управления. Статика проходит через Worker для применения заголовков. На GitHub Pages эти серверные заголовки не применяются. Ошибки API не раскрывают внутренние исключения или ответы Telegram.

Открытый ранее токен удалён из текущих main-файлов mklending и ai-lending-test, но остался в старых коммитах. Его обязательно отозвать в BotFather. История Git не переписывалась. До отзыва прежний токен считается скомпрометированным.
